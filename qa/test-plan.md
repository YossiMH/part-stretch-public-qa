# Native Safari public-file tests

This is a newly written public test specification. It contains no product implementation or private test/validator copy. Pure tests do not establish a browser result. Integration tests use real native Safari and real files; the guest run uses only `https://part-stretch-free.pages.dev/`, release `9b0731642df08c879cbea912b6ff7daf3401a164`, with the observed `guest-beta` services marker. Desktop Safari is not physical iOS. Account, cloud storage, purchases, receipts, refunds and interrupted checkout remain on their separate service-enabled path.

## Permanent pure commands and initial failure

Run from this repository's candidate root, the directory containing `qa/`, with installed Python:

    python3 -E -S -B -m qa.test_stl
    python3 -E -S -B -m qa.test_webdriver_boundary

Use the same flags with the installed Python executable on Windows. `-E` ignores Python environment overrides; `-S` excludes site packages, preventing an installed package named qa from replacing this namespace; `-B` prevents bytecode output. Before the implementation modules are added, the expected initial failures are specifically missing `qa.stl` and `qa.webdriver`, respectively, after AST syntax and namespace-module path checks. No placeholder implementation or deliberate raised production error is needed. The separate runner retains actual commands, traceback, exit status and exact candidate hashes; an unexpected import path or syntax error is broken setup, not the intended result. No native job is needed to demonstrate those missing pure capabilities.

The tests are permanent and must remain runnable unchanged after implementation. They use literal serialized messages and mathematical geometry as data, never mocks, stubs, patched functions, fake network services or a fake driver. The test module's own cuboid/tetrahedron construction and binary/ASCII serialization provide independent inputs; expected dimensions/volumes are specified numbers, not results generated by the validator. `main()` runs every case and fails on any exception. Protocol JSON booleans are external data, not stored application state.

## Pure API contract

All APIs below are synchronous pure functions. They perform no filesystem, network, browser, logging, clock or environment access and mutate no caller-owned input. Implement them with explicit types and functional code; no OO wrappers, stored boolean state, duplicated state authority or callback-driven changes. Each rejection is `ValueError(code)` with exactly one stable string argument; never print raw input or silently return success/default data.

`Point = tuple[float, float, float]`; `Triangle = tuple[Point, Point, Point]`; `Bounds = tuple[Point, Point]`, in millimetres. `qa.stl` exports:

- `make_cuboid_stl(size_mm: Point, encoding: str) -> bytes`: deterministic complete origin-based, closed, 12-triangle cuboid; encoding is exactly `binary` or `ascii`. Every side must be finite and positive; reject otherwise with `CUBOID_DIMENSIONS`. Unsupported encoding is `STL_ENCODING`. Runtime callers create a fresh task-named fixture file from these bytes; no customer file or copied private fixture.
- `parse_stl(content: bytes) -> tuple[Triangle, ...]`: consume the complete binary or ASCII STL, returning each triangle's three vertices in serialized order. Check every normal and vertex for finiteness, including the last record. A valid binary file is 80 header bytes, uint32 little-endian count, then exactly count×50 bytes; arbitrary header/attribute bytes are permitted. A binary header beginning `solid` is still binary when its complete count/length matches. ASCII requires complete `solid`, facet normal, outer loop, exactly three vertices, endloop/endfacet, and endsolid grammar; whitespace is allowed, additional tokens are not. Reject no triangles/empty data with `STL_EMPTY`, binary count/length/truncation/trailing data with `STL_BINARY_LENGTH`, malformed/incomplete/trailing ASCII with `STL_ASCII_SYNTAX`, and any NaN/Infinity normal or coordinate with `STL_NONFINITE`. Preserve no hidden partial result after rejection.
- `validate_stl(content: bytes, expected_bounds_mm: Bounds, expected_volume_mm3: float, *, abs_tol_mm: float = 0.0001, abs_tol_mm3: float = 0.001) -> dict[str, object]`: use complete parsing; reject zero-area faces (`STL_DEGENERATE`), open/nonmanifold or inconsistently directed shared edges (`STL_TOPOLOGY`), wrong min/max coordinates (`STL_BOUNDS`) and wrong absolute signed volume (`STL_VOLUME`). Compare each coordinate/volume using the declared absolute tolerance, not display rounding. A consistently reversed closed surface is accepted and retains negative signed volume; one reversed face is not. Normals may be zero but must be finite. Return exactly `format` (`binary`/`ascii`), `byte_count`, `triangle_count`, `bounds_mm` (two Point tuples), `signed_volume_mm3` and lowercase `sha256` of all input bytes. The validator is generic: a closed tetrahedron with the same bounds is valid at its own volume and fails an expected cuboid volume. Do not special-case filenames, sizes or test identities.

`qa.webdriver` exports:

- `parse_webdriver_response(http_status: int, body: bytes) -> object`: strict UTF-8/JSON; reject malformed/trailing/nonfinite JSON with `WEBDRIVER_JSON`; require an object with `value`, otherwise `WEBDRIVER_ENVELOPE`. A `value` error object must have a nonempty string error code; raise `WEBDRIVER_REMOTE_ERROR:` plus that code without its message/stack/session. Check remote errors even on HTTP200; otherwise reject non-2xx HTTP with `WEBDRIVER_HTTP_STATUS`. Preserve a valid value's representation, including null, arrays and protocol booleans; do not coerce missing/error data into those values.
- `admit_native_session(host_system: str, capabilities: object) -> dict[str, str]`: exact `Darwin` host or `NATIVE_MACOS_REQUIRED`; capabilities must be an object whose browserName lowercases to exactly `safari`, otherwise `NATIVE_SAFARI_REQUIRED`. browserVersion must be a nonempty, non-whitespace string or `NATIVE_SAFARI_VERSION_REQUIRED`. Return only `browser_name: safari` and the observed `browser_version`. A UA string, WebKit, preview build, simulator or Chrome cannot replace the native identity. This pure validation alone cannot prove where the supplied observations originated; runtime must obtain them from the real Mac and Apple driver.
- `write_next_action(operation_id: str, observed_id: str, outcome: str) -> str`: pure decision only, never an HTTP call or retry. Empty operation ID is `WRITE_ID_REQUIRED`; any nonempty foreign observed ID is `WRITE_ID_MISMATCH`. `not-dispatched` with no observed receipt and `confirmed-not-executed` with a matching receipt permit `dispatch-once`. A matching completed receipt returns `retain-result`; a matching refusal returns `stop-refused`. `unknown`, with no receipt or the matching ID, returns `inspect-same-operation`. Completed/refused/confirmed-not-executed without a receipt is `WRITE_OBSERVATION_REQUIRED`; unsupported outcomes, including timeout/failed/retry, and not-dispatched with a matching receipt are `WRITE_OUTCOME`. A timeout must be classified unknown by the real effect owner. No absent, unrelated, refused or uncertain response authorizes a repeat.

## Native CLI and real integration

Green adds `qa/native_safari.py`, `qa/file-controls.html` and manual-only `codemagic.yaml` in addition to the pure modules. Required commands are:

    python3 -E -S -B -m qa.native_safari integration --output DIR --run-id ID --deadline-seconds 55
    python3 -E -S -B -m qa.native_safari guest --output DIR --run-id ID --deadline-seconds 55
    python3 -E -S -B -m qa.native_safari controls --output DIR --run-id ID --deadline-seconds 55

`DIR` is a new task-owned output directory; `ID` is the pre-journaled unique operation identity. Each phase has a 55-second body and at most five seconds of cleanup. Missing/invalid arguments fail before browser actions. Integration, guest and controls emit separate JSON results, return nonzero on any failed automated assertion/capture/cleanup, and preserve the original failure if diagnostics/cleanup also fail. Exit0 means those automated checks completed; actual image viewing remains explicitly pending until the executor performs it. A zero exit or passed CI job cannot close Safari without the required viewed native images, WebGL and all other observations. Actual resources belong to the phase: real `/usr/bin/safaridriver`, native session, task-owned static server and exact task-named files. Read actual OS, Safari short/build and driver/session versions; compare Safari to Apple's current stable release. No Playwright WebKit, UA substitution, simulator, dependency installation or private data.

Integration serves the newly written public static page and fixture over task-owned loopback HTTP. Use standard WebDriver file-input selection, then supported read-only File APIs to verify the selected file's complete bytes/hash. Click a real fixture download link once, observe the exact new filesystem file and compare complete bytes/hash. The static file is the independently generated fixture, not a fake product response; integration does not establish app behavior. Do not assign files with JavaScript, create File/DataTransfer objects, fake a download, use product internals, change security/permissions or inspect unrelated Downloads files. An unsupported file path/control or permission remains a failure with the precise missing capability.

## Actual public guest requirements

Run only after the integration result passes and is retained. Require actual loaded public release/services, record the native session and use normal WebDriver input/click/keyboard/pointer operations. The public HTML currently exposes `#file`, `#choose`, `#choose-exact`, `#start`, `#end`, `#delta`, `#target`, `#undo`, `#view`, `#dimensions`, `#original-dimensions`, `#download`, and `#resume-local-job`/`#resume-unpaid-edit`; observing a selector is not completing its behavior. Use observable readiness or error conditions with finite waits, preserving last selected DOM diagnostics on failure.

1. Generate/import a fresh 17×11×7 mm origin-based STL. Validate all input bytes, bounds and 1309 mm³ volume. Confirm actual loaded filename, preview and numeric dimensions. Through normal controls choose X, exact band 5..12 and Keep start end fixed (`data-anchor="1"`), then add 3 mm along X to produce 20×11×7 mm with bounds (0,0,0)..(20,11,7). The selected-region `#target` changes 7→10; it is not whole-model length 20. Retain actual region, anchor, delta, target and dimensions.
2. Reload, use the visible normal Resume control and verify the same local edit/settings/model remain 20×11×7 mm. Do not inject localStorage, browser state or an app object. Exercise interrupted local-work preservation through normal page controls; a lost or replaced edit fails.
3. Click the actual product Download once. Pre-journal that operation; wait for its exact new completed STL, never merely a partial filename/size. Fully read and validate structure, all finite geometry, closed consistent topology, origin-based bounds and 1540 mm³ volume. Retain file byte count, triangle count, complete SHA256 and signed volume. A dimensions-only check fails this requirement.
4. Reimport that exact downloaded path through the supported ordinary file control. Hash it again and require the same bytes/hash and 20×11×7 mm model; a regenerated equivalent fixture is not a reopen. Preserve the original selected file and output identities.
5. In the controls phase, independently generate/import 20×10×6 mm (1200 mm³). Select X band 5..15, Keep start end fixed and +4 mm, requiring 24×10×6 mm with bounds (0,0,0)..(24,10,6); selected target is 14 mm. Attempt delta −11 mm, beyond the ten-millimetre band's valid range; require the visible rejection and unchanged last valid geometry. Use normal Undo to clear the rejected change and recover a valid recorded operation; if that recovers the +4 mm state, Undo that change as well. Within those two actions require the original 20×10×6 mm operation/model, with region/delta/dimensions checked after each action. Do not weaken this to checking the error label or Undo button existence. This phase does not require another product Download; 1440 mm³ is the expected 24×10×6 cuboid volume, not a measured exported volume unless actual bytes are separately obtained.
6. Exercise normal orbit/pan/zoom and keyboard focus with visible layout at the actual recorded viewport. Required controls must be usable and not clipped/covered; selected fields retain focus during typing and ordinary Tab order reaches the controls. Retain the viewport, exercised actions, focused element, before/after camera-view screenshot and unchanged model dimensions; do not claim physical-phone usability from a desktop viewport.

Observe actual model images and WebGL separately. Read an existing primary canvas context/version only after successful normal model adoption establishes the app already owns its context. Never create a replacement/probe context or patch page functions. Require actual WebGL2 identity/version and visible model rendering; Canvas2D, a canvas rectangle, Safari version or an unviewed PNG cannot pass. Capture native images after import/edit/reopen and the exercised view action; each phase must record what was actually captured/viewed and what remains unavailable.

## Time, collection and failure

Only public QA `YossiMH/part-stretch-public-qa` is a publication destination. Whitelist: `codemagic.yaml`, this file, the two test modules, `qa/stl.py`, `qa/webdriver.py`, `qa/native_safari.py`, `qa/file-controls.html`. Do not export private code/tests/validators/configuration/fixtures, credentials, customer files, browser profiles or handoff data. Runtime output is never committed to that whitelist.

Use only manual `mac_mini_m2`, five minutes whole-job maximum, at most 240 seconds combined script work and bounded commands/HTTP/startup/poll segments of at most 60 seconds. Integration must pass before guest begins; all required phases must pass for the run to pass. Before dispatch read actual Free Personal remainder/billing-off state and reserve the five-minute maximum plus five retry minutes. A reserve is not retry permission. Journal exact source/config/account/application/job identities, timestamps, pre/post balance and actual debit; displayed unchanged accounting may lag. No billing/card/paid upgrade or automatic trigger.

Emit one `PUBLIC_QA_RESULT ` line followed by JSON for each phase: `format_version: 1`, `run_id`, `phase`, `result: automated-checks-passed|failed`, `image_observation: pending-executor-view`, source-file hashes, actual OS/bundle/driver/session versions, named checks with their observations, selected file hashes/measurements and any original failure. Keep the same JSON in the phase's output file; the executor's separate actual image-view result must name that image's SHA256 before final acceptance. Emit each real PNG in `PUBLIC_QA_IMAGE ` JSON records containing `run_id`, `phase`, `name`, `png_bytes`, `sha256`, zero-based `chunk_index`, `chunk_count` and `base64`; use consecutive 4096-character chunks except the last. All records for one image must agree, consume every byte, and match the final decoded SHA256.

Limit each PNG to 256 KiB and the complete encoded image records for the job to 1 MiB; retain original files. Exceeding a limit or truncated/unavailable logs is incomplete image collection, never synthetic pixels or a viewed-image claim. The executor must assemble only actual ordinary log output, verify decoded PNG/hash, save and view it with a supported image tool. CM-R must reconcile that observation. No entire page/environment/raw session, capability URL or private screenshot in logs. Do not use blocked ZIP URLs, `locator.downloadMedia`, hidden provider APIs or browser security workarounds.

Every uncertain create-session, upload, edit, Download, reopen or dispatch keeps its original identity and receipt for read-only reconciliation. Repeat only a read-only operation or one confirmed not executed, with finite bounds. Real native failures produce selected diagnostics and the original error, then a targeted tested correction; never fabricate a pass, weaken customer assertions or infer a product defect from a missing capability/collection result. Retain first preflight failure as unknown cause even though the unchanged second condition passed.

These tests cannot satisfy physical phone/tablet, actual iOS or truthful support-decision, private account/history/original/settings/purchased/latest-file, TEST payment/refund/receipt, interrupted checkout, support/privacy/measurement/costs, beta, both promotions or paid-launch requirements. Those remain required separately; no public Mac result enables beta or live charging.
